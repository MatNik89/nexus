## 1. Executive Summary & Verification Matrix

The Round 1 fold (`7c68cda` and `5fedd4e`) addressed the eight architectural findings from Round 1:
1. **Capability Seal Enforcement (codex #1):** `liveProbes` + `Seal` execute prior to consumer initialization. An `OFF` state for `conversation` exits 1 immediately; Telegram adapter `Run` is gated on `snap.On("telegram")`. Causal detector `TestSealedOffCapabilityNeverServes` was verified.
2. **Reminder Delivery Receipts & Idempotency (codex #2 / kilo #3):** `channel.EnqueueReplyID` enforces PK-idempotency across crash recovery. `deliverPendingReminders` queries `DeliveryStatus == "SENT"` before minting delivery receipts. Causal detector `TestReminderReceiptOnlyFromSent` was verified.
3. **Doctor P0 Grant Honesty (codex #3 / kilo #1):** `nexus doctor --p0` no longer self-certifies. It requires an external acceptance attestation (`acceptance.json`) generated by `scripts/p0-accept.sh` bound to the SHA-256 digest of `os.Executable`. Causal detector `TestDoctorP0GrantLive` was verified.
4. **`telegram_api_base` Validation (codex #4 / kilo #5):** `config.ValidateBounds` restricts `TelegramAPIBase` to `https://api.telegram.org` or loopback HTTP/HTTPS (`127.0.0.1`, `localhost`, `[::1]`). Causal detector `TestTelegramAPIBaseLoopbackOnly` was verified.
5. **Acceptance Harness Build Isolation (codex #5):** `acceptance_linux_test.go` uses package-scoped temporary build directories in `TestMain` and respects `NEXUS_ACCEPT_BIN`.
6. **Causal No-Channel Sensitivity (codex #6 / kilo #2):** `TestCriterion3SensitivityNoChannel` runs a channel-less daemon first, verifying overdue occurrences stay `DELIVERY_PENDING` without spurious receipts.
7. **Deterministic Owner Chat Selection (kilo #4):** `ownerChat` deterministic resolution selects the lowest chat ID bound to the profile.

However, during verification of the full test suite (`CGO_ENABLED=0 go test -count=1 ./...`), a **material race condition / design defect** was uncovered in the interaction between `deliverPendingReminders` (asynchronous polling ticker) and `telegramHandler` (immediate user ack handling), causing `TestCriterion3ReminderDeliversAfterRestart` to fail.

## 3. Findings & Defect Analysis

### Finding 1: [HIGH / REVIEW-BLOCKER] Asynchronous Polling Race between Outbox `SENT` and `MarkDelivered` Rejects Valid User Acks

- **Severity:** High (Review Blocker)
- **Locations:**
  - [`cmd/nexus/main.go:198-210`](file:///home/matej/HARNESS/nexus/cmd/nexus/main.go#L198-L210) (2-second ticker for reminder delivery)
  - [`cmd/nexus/main.go:894-914`](file:///home/matej/HARNESS/nexus/cmd/nexus/main.go#L894-L914) (`deliverPendingReminders`)
  - [`cmd/nexus/main.go:1056-1064`](file:///home/matej/HARNESS/nexus/cmd/nexus/main.go#L1056-L1064) (`telegramHandler` handling `ack <occ>`)
  - [`internal/obligation/obligation.go:834-858`](file:///home/matej/HARNESS/nexus/internal/obligation/obligation.go#L834-L858) (`Manager.MarkAcked`)
  - [`internal/acceptance/acceptance_linux_test.go:307-313`](file:///home/matej/HARNESS/nexus/internal/acceptance/acceptance_linux_test.go#L307-L313) (`TestCriterion3ReminderDeliversAfterRestart`)
- **Mechanism:**
  1. When a reminder fires, it is placed in state `DELIVERY_PENDING`.
  2. The background goroutine in [`cmd/nexus/main.go:198-210`](file:///home/matej/HARNESS/nexus/cmd/nexus/main.go#L198-L210) runs `deliverPendingReminders` on a 2-second ticker (`time.NewTicker(2 * time.Second)`).
  3. On Tick 1, `deliverPendingReminders` calls `EnqueueReplyID`, which creates an outbox row in status `PENDING`. At that instant, `b.chanCore.DeliveryStatus(ctx, dlvID)` is `"PENDING"`, so `deliverPendingReminders` skips `MarkDelivered` and exits.
  4. In parallel, `telegram.Adapter.Run` calls `chanCore.Flush`, delivers the HTTP message to Telegram, and marks the outbox row as `SENT` (`EvOutboundSent`).
  5. The user receives the reminder on Telegram and immediately responds with `ack occ-...`.
  6. `telegram.Adapter` receives the incoming message and invokes `telegramHandler`.
  7. `telegramHandler` calls `b.obl.MarkAcked(ctx, occ, ...)`.
  8. `MarkAcked` checks [`internal/obligation/obligation.go:838-844`](file:///home/matej/HARNESS/nexus/internal/obligation/obligation.go#L838-L844):
     ```go
     st, deliveredAt, deliveredBy, err := m.occurrenceDelivery(ctx, occ)
     if err != nil {
         return err
     }
     if deliveredAt.IsZero() || deliveredBy == "" {
         return fmt.Errorf("obligation: ack refused — no durable delivery receipt for occurrence %s (B5)", occ)
     }
     ```
  9. Because the 2-second ticker in `deliverPendingReminders` has **not ticked a second time yet**, `MarkDelivered` has not been called, and no `EvDelivered` event exists in the journal. The occurrence is still in state `DELIVERY_PENDING`.
  10. `MarkAcked` fails with `"obligation: ack refused — no durable delivery receipt for occurrence ... (B5)"`.
  11. The daemon sends an error message back to the user: `"Ack failed: obligation: ack refused — no durable delivery receipt for occurrence occ-rem-accept#1 (B5)"`.
- **Observed Test Failure:**
  During `go test -count=1 ./...`, `TestCriterion3ReminderDeliversAfterRestart` failed:
  ```text
  --- FAIL: TestCriterion3ReminderDeliversAfterRestart (22.66s)
      acceptance_linux_test.go:312: no outbound message containing "Acknowledged occ-rem-accept#1"; sent=[Reminder: water the plants (reply: ack occ-rem-accept#1) Ack failed: obligation: ack refused — no durable delivery receipt for occurrence occ-rem-accept#1 (B5)]
  FAIL
  FAIL	github.com/MatNik89/nexus/internal/acceptance	57.681s
  ```
- **Remediation:**
  In `cmd/nexus/main.go`, when `telegramHandler` encounters `case strings.HasPrefix(lower, "ack "):`, before calling `b.obl.MarkAcked`, it should resolve any pending delivery receipt for that occurrence (e.g. by checking `b.chanCore.DeliveryStatus(ctx, deliveryIDFor(occ))` and calling `b.obl.MarkDelivered` if status is `"SENT"`, or invoking `deliverPendingReminders(ctx, ownerChat)` inline).

## 4. Top 3 Weakest Points

1. **Decoupled Asynchronous Polling for Delivery Receipts ([`cmd/nexus/main.go:200-209`](file:///home/matej/HARNESS/nexus/cmd/nexus/main.go#L200-L209), [`cmd/nexus/main.go:894-914`](file:///home/matej/HARNESS/nexus/cmd/nexus/main.go#L894-L914)):** Polling `DeliveryStatus` on a periodic 2-second ticker introduces an asynchronous window where an outbox message has been proven `SENT` and delivered to the user, but the obligation subsystem has not yet recorded `EvDelivered`. Any fast user interaction (or automated test push) within that 2-second window is rejected as lacking delivery evidence.
2. **Acceptance Attestation Path Assumption in `scripts/p0-accept.sh` ([`scripts/p0-accept.sh:17`](file:///home/matej/HARNESS/nexus/scripts/p0-accept.sh#L17)):** `p0-accept.sh` writes `acceptance.json` to `${XDG_CONFIG_HOME:-$HOME/.config}/nexus/system/acceptance.json`. If a user or test runs `nexus` with a custom `NEXUS_DIR` or non-standard `pathx.Layout`, `doctor --p0` will fail to locate the attestation.
3. **Resource Leak in Doctor Telegram Probe ([`cmd/nexus/main.go:872-887`](file:///home/matej/HARNESS/nexus/cmd/nexus/main.go#L872-L887)):** `mustProbeCore` creates disposable journal directories under `/tmp` without closing or removing them.
