# PHASE-1A verification round 4 — Codex

Scope: `slice/p0-phase1` at `ea8558b54401543797dfe5167076e3c50ef9fcd9`, restricted to the seven round-3 folds and defects introduced by this commit.

- `go test -count=1 ./internal/...` — PASS.
- `go test -count=20 ./internal/kernel/journal ./internal/kernel/contracts ./internal/security/redact` — PASS.
- Two read-only Go-overlay negative probes — both RED: an oversized Unicode-escaped secret survived redaction; a case-aliased `TURN_ID` resurrected after clearing.

1. **[OK] The chain encoding and open-time consistency fold is correct.** `chainInput` now length-prefixes every variable-width field, distinguishes nullable `sealed_payload_ref` with an explicit presence byte, and includes the envelope length (`internal/kernel/journal/journal.go:50-78`). `verifyChainFull` verifies the hash, parses the stored envelope, and compares its event ID, run ID and sequence to the denormalized columns before `Open` can serve (`journal.go:475-513`). This closes the delimiter and NULL/empty collisions from round 3.

2. **[UNFOLDED] The mandatory structural-secret code is fixed, but the promised 10-field RED is not fully causal.** `Redactor` now requires `Touches`, `None` implements it, and `ParentEventID` is inspected (`internal/security/redact/redact.go:17-23,164-182`; `internal/kernel/journal/journal.go:303-326,340-347`). However the `event_type` subtest changes the type to `x-<secret>`, which is absent from `manyEvents`; admission rejects it at the closed event registry before `Touches` runs (`journal_test.go:172-202`; `journal.go:334-345`). Removing event-type secret inspection would leave that RED green. Register the mutated event type for that subtest or use a test redactor that records/asserts its `Touches` call.

3. **[NEW-ERROR] Verify-before-lease introduces a writer-handoff TOCTOU, and lease-release failure is silently reported as success.** A second opener verifies and caches `(lastOffset,lastHash)` before checking ownership (`internal/kernel/journal/journal.go:204-225`). The live writer can append and close between that snapshot and the new lease transaction; the opener then acquires the now-free lease but starts its actor from stale state (`journal.go:227-277`), causing subsequent appends to collide at the already-used offset until restart. Acquire ownership first, then verify/recover under that ownership, releasing the exact token on every failure. Additionally, `Close` discards the `DELETE` error and returns only `db.Close` (`journal.go:522-533`); a busy/I/O failure can therefore return nil while leaving a live same-PID lease that blocks reopen. Preserve both errors. Add a barrier-synchronized append/close/open handoff RED and an injected lease-delete failure RED.

4. **[OK] The event registry is now defensively closed.** `Open` validates non-empty names and copies every entry into a private map before the actor starts (`internal/kernel/journal/journal.go:207-220`). The post-open caller-map mutation RED targets the production `Open`/`Append` path and would fail if the alias were restored (`journal_test.go:327-341`).

5. **[UNFOLDED] Exact-key deletion does not prevent known optional fields from being resurrected through JSON aliases.** Go's `encoding/json` accepts case-insensitive matches for struct tags, but `MarshalJSON` deletes only exact lowercase names from preserved `Wire` (`internal/kernel/contracts/contracts.go:60-98`). A wire envelope containing `"TURN_ID":"turn-9"` parses into `TurnID`; after `TurnID` is cleared, marshal preserves `TURN_ID` as supposedly unknown, and the next parse restores `turn-9`. The new RED covers only canonical lowercase `turn_id` (`contracts_test.go:439-461`). A production-code overlay probe reproduced the resurrection. Either reject non-canonical/case-aliased known keys during parsing or remove preserved keys using the same case-folding rules as the decoder; table-test every optional.

6. **[NEW-ERROR] The redaction budget fails open for semantically escaped secrets.** Under-budget JSON is now decoded once and walked linearly, but inputs over 1 MiB or over depth 64 fall back to raw byte replacement (`internal/security/redact/redact.go:64-70,137-161`). Raw matching cannot see decoded equivalents such as `s\\u0065cret`. A production-code overlay probe built valid JSON just over `maxJSONBytes`; with known secret `secret`, `Redact` returned JSON whose decoded value was still exactly `secret`. `Journal.Append` accepts and persists that result. Budget excess must return a typed rejection (or use a bounded streaming token transform), never a byte-level fallback for valid JSON; add byte-limit and depth-limit escaped-secret REDs.

7. **[UNFOLDED] The new admission barrier exercises the right window but is not revert-proof.** The actor pauses after commit and before reply, and current `Append` correctly waits only for the reply (`internal/kernel/journal/journal.go:280-300,407-420`; `journal_test.go:343-375`). But the test calls `cancel()` and immediately releases the actor. Under the old incorrect post-admission `select { reply | ctx.Done }`, both channels may be ready before the Append goroutine runs, so Go may choose the reply and leave the RED green. While the actor remains blocked, first prove cancellation alone cannot return from `Append`; only then release it and require the committed result.

8. **[OK] The nonce lease closes the original same-process two-handle hole in the uncontended path.** A live `(pid,starttime,nonce)` holder is rejected regardless of whether it shares the current PID, and `Close` conditionally deletes only its own token (`internal/kernel/journal/journal.go:227-275,522-533`). The real simultaneous two-handle and failed-verification/no-lease tests exercise those stated cases (`journal_test.go:280-325`). Finding 3 is a new handoff/error-path defect, not a denial of these local fixes.

VERDICT: FAIL
