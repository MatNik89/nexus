4. [NEW-ERROR] **`ProjTx.QueryRow` suppresses the required guard error.** For a canonical-table query, it discards `NON_CANONICAL_WRITE` and returns a synthetic row whose `Scan` yields only `sql.ErrNoRows` (`internal/kernel/journal/projection.go:48-54`). The same prohibited access therefore produces the specified error through `Exec`/`Query` but masquerades as absent data through `QueryRow`, allowing callers to treat a policy rejection as ordinary state. Fix: return an error-capable restricted row wrapper, or remove `QueryRow` and require `Query` where guard failure can be surfaced; add a QueryRow-specific RED.

5. [OK] **Codex #9/#10 are materially folded.** `Step` returns the unchanged current state on rejection, and `Fold` now consumes typed events, reports the last successful checkpoint and each intermediate state (`internal/kernel/machine/machine.go:48-89`). 6. [NEW-ERROR] **`Fold` trusts arbitrary/non-monotone offsets and can regress its checkpoint.** Nothing rejects zero, duplicate, or decreasing offsets (`internal/kernel/machine/machine.go:75-89`). A legal event sequence tagged offsets `10, 9, 9, 2` succeeds and returns checkpoint 2, despite claiming journal-offset checkpoint semantics. This can make resume replay already-applied events or persist a checkpoint behind state. Gaps are legitimate after entity filtering, but offsets must be strictly increasing (and a resumed fold needs an explicit prior checkpoint). Add decreasing/duplicate/zero offset REDs.

9. [NEW-ERROR] **Environment-name case folding creates an unvalidated duplicate/overwrite channel.** Linux environment names are case-sensitive, but `envLayer` lowercases every suffix and assigns into a map without collision detection (`internal/foundation/config/config.go:172-190`). Thus `NEXUS_CFG_PROVIDER_MODEL=a` plus `NEXUS_CFG_provider_model=b` is accepted as one key with order-dependent last-write-wins behavior; the lowercase name should instead be unknown under the documented uppercase namespace. The same collision can erase a value before final bounds validation. Require canonical uppercase names and reject duplicate normalized keys; test both input orders.

10. [NEW-ERROR] **Strict env parsing can echo the entire rejected value into diagnostics.** `parseBoolStrict` includes raw input with `%q` (`internal/foundation/config/config.go:111-119`). A mistyped secret placed in `NEXUS_CFG_SANDBOX_DISABLED` is copied into the startup error, contrary to the repository's no-secret diagnostic posture. Report key/origin and bounded metadata only, never raw configuration values; add a canary no-echo RED.

11. [UNFOLDED] **Codex #15 checks only a final-component symlink, not symlinked path components.** `EnsureDir` calls `MkdirAll` and then `Lstat(path)` on the final path (`internal/foundation/pathx/pathx.go:77-101`). If a parent component is a symlink, the final directory is real, private, and caller-owned, so verification passes while storage is redirected. The test covers only `path` itself being a symlink (`pathx_test.go:44-66`). Either explicitly permit trusted parent symlinks and narrow the claim, or walk/open the owned subtree with no-follow semantics and test a symlinked parent; the current comment claims refusal of the latter.

12. [NEW-ERROR] **`Terminate` can leave a TERM-resistant group member alive when the leader exits promptly.** After group TERM, the select returns as soon as the leader's `Wait` completes (`internal/foundation/procx/procx_linux.go:116-128`). The subsequent “straggler” KILL calls `signalGroup`, which refuses to signal once the leader token is dead (`procx_linux.go:107-115,129-135`). Scenario: leader exits on TERM, same-PGID grandchild ignores TERM; no KILL is sent, `groupSurvivors` reports an error, and the owned child is leaked. This violates T10's termination acceptance even under the newly narrowed group scope. The REDs do not combine a TERM-exiting leader with a TERM-resistant child. Fix: retain safe member identities or keep the leader unreaped while enforcing the grace/KILL phase; add that exact process-group fixture.
