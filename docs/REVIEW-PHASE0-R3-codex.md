1. **[UNFOLDED] `FloorProbe` uses an ambiguous substring as proof that the in-sandbox ptrace sentinel ran.** The production path is now invoked, but any failed bwrap launch whose combined output contains lowercase `denied` is accepted (`internal/preflight/probe/probe.go:64-80`). A fake bwrap that returned `bwrap: setup failed: Permission denied` without launching any target produced all five doctor checks as `OK`, `prerequisites-ready`, and `doctor --strict` exit 0. Thus T03 can still report the sandbox floor healthy when namespace or pre-exec setup is broken, contrary to its per-prerequisite fail-closed acceptance (`docs/tasks-P0.md:41-51`). Require a unique, exact sentinel emitted only after the ptrace syscall (for example `NEXUS_PTRACE_DENIED:EPERM`) plus the expected child exit status; ordinary bwrap diagnostics must remain OFF. Add the fake-prelaunch-`Permission denied` RED.

2. **[UNFOLDED] The workdir guard blocks `/` but still allows non-disposable, overbroad and cooperatively writable host trees.** Its “shallow” rule only requires two path components, so the current user's entire home directory `/home/matej` is accepted as a recursive RW bind (`internal/preflight/probe/probe.go:264-291`). The implementation also claims to reject “group/world-writable” paths but tests only the world-write bit and deliberately accepts `0770`/`0775`; a fresh test confirmed both `/home/matej` and a `0770` directory are accepted. Ownership by UID does not make a shared-group directory single-user controlled. This preserves the concrete host-exposure part of round-2 finding #2 and violates E10/B4's “disposable RW workdir” contract (`docs/ARCHITECTURE-ESSENTIALS.md:129-136`; `docs/HARDQ-CONSOLIDATED.md:79-88`). Until T25 supplies a policy-owned directory capability, Phase 0 should require a dedicated allowed root and reject `mode&0022 != 0`; add home/outside-root, foreign-owner, group-write and world-write REDs. The documented same-user bind-by-path TOCTOU ceiling may remain deferred to T25, but it does not justify the broader grants.

3. **[NEW-ERROR] The replacement ELF resolver does not implement Linux loader RUNPATH/RPATH semantics and rejects ordinary valid binaries.** Root `DT_RUNPATH` entries are used literally and globally (`internal/preflight/probe/probe.go:148-157,207-230`): `$ORIGIN`/`${ORIGIN}` are not expanded relative to the referring object, `DT_RPATH` is ignored, and each transitive library's own RUNPATH/RPATH is ignored (`internal/preflight/probe/probe.go:231-259`). A fresh executable linked with `RUNPATH [$ORIGIN/../lib]` ran as a valid host ELF but `resolveClosure` failed with `cannot resolve library "libnexusr3foo.so"`. This makes E10's promised “resolved loader/library dependencies” false for a common deployment shape. Resolve each dependency in the context of its referring ELF, implement the documented dynamic-loader token/search rules needed by the P0 contract (including old-dtags RPATH), and add self-contained RUNPATH, RPATH and transitive-per-object fixtures.

4. **[UNFOLDED] The advertised closure budgets do not bound the expensive allocations they are meant to control.** `add` calls `os.ReadFile` before checking the aggregate 256 MiB limit (`internal/preflight/probe/probe.go:163-191`), and PT_INTERP allocates attacker-declared `p.Filesz` with no limit before any closure accounting while ignoring `ReadAt` failure (`internal/preflight/probe/probe.go:195-205`). `ImportedLibraries` results and the BFS queue are likewise materialized/appended without a dependency-count or metadata-size bound before the 64-file check (`internal/preflight/probe/probe.go:213-259`). A promoted hostile ELF can therefore consume unbounded memory before returning the nominal budget error. Stat/open and reject oversize files before allocation, cap PT_INTERP to a small absolute path limit, treat parse/read errors as fatal, and debit/enforce dependency nodes before enqueueing.

5. **[NEW-ERROR] The new sealed `Handle` has an invalid repeat-Start transition that loses ownership of a live child.** A second `Start` calls `exec.Cmd.Start` again, receives an error, resets `started=false`, and calls `Close` (`internal/preflight/probe/probe.go:332-339`). `Wait` then skips `cmd.Wait` because `started` is false (`internal/preflight/probe/probe.go:351-359`), so the first-started process is not reaped through the handle. Reject `Start` before touching `exec.Cmd` when the handle is already started/closed, preserve the state of the first launch, and add repeat-Start plus Close-before/after-Start lifecycle tests. The private command, copied hash map, owned closure/filter FDs, one-shot close, and normal Start/Wait cleanup otherwise fold round-2 findings #5/#8 (`internal/preflight/probe/probe.go:294-369,414-457`).
