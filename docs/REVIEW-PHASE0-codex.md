# PHASE-0 code review — Codex (T01–T03)

Scope: `slice/p0-phase0` at `6fc4b1ebc16fe33ffaa8b0e74ff65df1be972fb5`.

Evidence run on 2026-09-03:

- `go vet ./...` — PASS.

1. **[BREAK] P0 has no SYSCALL-floor enforcement or test, despite T02 requiring five capability columns.** The implementation describes and exercises only FS_RO, FS_RW, NET_DENY and PROC_TREE; the bwrap argv supplies no seccomp filter, and the report contains no denied-syscall case (`internal/preflight/probe/probe.go:1-5,82-115`; `docs/PROBE-REPORT-2026-09-03.md:15-38`). T02 explicitly requires `SYSCALL-floor`, and the owner design defines it as a distinct capability with a hostile denied-syscall RED (`docs/tasks-P0.md:26-32`; `docs/DESIGN-S0-sandbox-codex.md:946-990,1230-1237`). A command can therefore make unrestricted non-namespace syscalls while the suite reports full success. **Fix:** either install a versioned, architecture-specific seccomp profile through bwrap and add a forbidden-syscall fixture plus mutation control, or mark SYSCALL `UNAVAILABLE` and fail the T02 gate; do not publish ENFORCED.

2. **[BREAK] The mounted runtime closure admits undeclared child executables.** `--ro-bind /usr /usr` plus `/bin` and `/sbin` symlinks exposes every executable under `/usr`, while the only child-exec test selects a path outside all mounts (`internal/preflight/probe/probe.go:82-87`; `internal/preflight/probe/probe_linux_test.go:163-177`). I reproduced `/work/probehelper exec /usr/bin/id` under this profile: it returned 0 and printed `exec ok`. That violates the locked rule that undeclared child executables are rejected (`docs/HARDQ-CONSOLIDATED.md:75-82`; `docs/ARCHITECTURE-ESSENTIALS.md:128-133`). **Fix:** bind only the promoted executable and its resolved, content-hash-bound loader/library files into a synthetic closure (or adopt another enforceable exec allowlist), and add an undeclared executable already present under `/usr/bin` as the hostile case.

3. **[RED] `runBound` does not test the launcher it claims to certify.** `Command` validates and emits the host helper path, after which the test rewrites raw argv to `/work/probehelper` and constructs a different `exec.Cmd` (`internal/preflight/probe/probe_linux_test.go:81-104`). Without that rewrite, a workspace target is either checked as `/work/...` where it does not exist on the host, or emitted as its host path where it is not visible in the sandbox (`internal/preflight/probe/probe.go:74-80,102-116`). Thus GREEN can coexist with a production launcher unable to launch the promoted artifact, and no test covers target identity across the host/sandbox mapping. **Fix:** make host source and sandbox destination explicit in the launcher contract, bind a pinned/hash-verified artifact, and execute the unmodified command returned by that API in every conformance test.

4. **[RED] The `/etc/shadow` test can pass without filesystem isolation.** It accepts any read error as proof (`internal/preflight/probe/probe_linux_test.go:66-79`), but the deployment account is already denied by ordinary host DAC (`host_shadow_readable=no`). The existing RO negative control proves that an explicitly mounted canary is readable; it does not show that the positive denial assertion fails when FS isolation is removed (`internal/preflight/probe/probe_linux_test.go:210-233`). This does not meet the red-capable hostile proof required by PRD §6 item 6 and T02 (`docs/PRD.md:46-53`; `docs/tasks-P0.md:27-39`). **Fix:** use the same host-readable, test-owned canary outside the declared closure for the deny assertion, then remove only FS isolation and require that exact assertion to turn RED; keep `/etc/shadow` as an additional literal contract case.

5. **[RED] PROC_TREE can pass vacuously, and its mandatory negative control is absent.** The test kills the entire host process group it created itself, so cleanup need not come from bwrap’s PID containment; afterward it searches `pgrep -f probehelper` (`internal/preflight/probe/probe_linux_test.go:181-207`). The spawned child was execed with argv0 `/proc/self/exe`, so that name is not a reliable survivor oracle (`cmd/probehelper/main.go:47-60`). `LoosenPIDNS` exists but is unused, while T02 requires a test-owned process-tree control whose loosened profile makes the boundary assertion fail (`internal/preflight/probe/probe.go:47-50,111-113`; `docs/tasks-P0.md:34-39`). **Fix:** have the helper report child and grandchild PID plus `/proc/<pid>/stat` start token over a pipe, kill only the sandbox leader through the production termination path, verify those exact identities disappear, and repeat with PID isolation disabled to observe RED. The missing control is material because the current positive oracle is independently non-causal.

6. **[BREAK] `nexus doctor` reports exec OK without checking the OS/kernel/user-namespace floor, functional bwrap usability, or the published minimum version.** `Run` collapses two prerequisites into `Detect`, but `Detect` only finds a PATH entry and accepts any successful `--version` output (`internal/preflight/doctor/doctor.go:54-72`; `internal/preflight/probe/probe.go:25-35`). An old bwrap, disabled unprivileged user namespaces, or a kernel policy that makes every launch fail still yields `sandbox-backend: OK`. The test table has no floor-failure injection; it labels two data-directory variants as two of “five prerequisites” (`internal/preflight/doctor/doctor_test.go:55-105`). This contradicts T03’s explicit floor-probe RED and F1’s separate OS/kernel-floor check (`docs/tasks-P0.md:41-51`; `docs/HARDQ-CONSOLIDATED.md:165-172`). **Fix:** add a separate injectable floor/functional probe, parse and enforce the published bwrap minimum, return distinct capability-scoped checks, and add the required forced-fail RED.

7. **[SEC] The production launcher API exposes switches that disable its security boundaries.** Any caller of the internal package can set `LoosenNet`, `LoosenPIDNS`, or an arbitrary `LoosenROBind`; the only guard is a comment (`internal/preflight/probe/probe.go:38-50,105-113`). A future well-meaning production caller can silently ship the negative-control profile, violating the constitution’s fail-closed sandbox rule (`CLAUDE.md:45-50`; `AGENTS.md:30-33`). **Fix:** keep the production `Spec` incapable of expressing weakened policy; place mutation-profile construction in a `_test.go`-only helper or an unexported test seam whose output cannot enter production launch paths.

8. **[SEC] Target and work-directory paths are neither pinned nor symlink-safe.** The target is opened only long enough to read four magic bytes, then closed and later executed again by path; `WorkDir` is bound verbatim with no canonical-root, symlink, ownership, or `(device,inode)` check (`internal/preflight/probe/probe.go:57-68,74-75,102-116`). A file or symlink swap between validation and bwrap exec can replace the promoted binary or redirect the RW grant. This directly misses the locked “resolved, hash-bound” closure (`docs/HARDQ-CONSOLIDATED.md:75-82`; `docs/ARCHITECTURE-ESSENTIALS.md:128-132`). **Fix:** resolve beneath an authorized root without symlinks, bind verified file descriptors/content-addressed artifacts, and reject identity changes immediately before launch; add target-swap and workdir-symlink REDs.

9. **[SEC] The bwrap profile grants `/etc/resolv.conf` although the locked file closure does not.** The allowlist names `/etc/ld.so.cache` and CA certificate files, never recursive `/etc`; the implementation silently adds resolver configuration (`internal/preflight/probe/probe.go:70-73,97-100`; `docs/HARDQ-CONSOLIDATED.md:75-82`). It is unnecessary for a NET_DENY process and widens host-information disclosure without a payer. **Fix:** remove the grant from the P0 profile; if a later network-enabled profile needs it, authorize and test that separate capability explicitly.

10. **[SEC] The doctor’s writability probe can follow and truncate a pre-existing symlink.** After a symlink-following `os.Stat`, it writes the predictable name `.doctor-write-probe` with `os.WriteFile`, ignores cleanup failure, and reports OK (`internal/preflight/doctor/doctor.go:102-127`). A same-user race or stale symlink can redirect the write to another user-writable file, and a data-directory symlink is accepted as if it were the intended directory. **Fix:** reject a symlinked data directory, open/verify the directory once, create a randomized probe with exclusive/no-follow semantics relative to that handle, and treat cleanup failure as OFF.

11. **[RED] T01’s static-link gate is fail-open for every `ldd` error.** The script interprets all nonzero `ldd` exits as “statically linked” (`scripts/static-check.sh:1-12`). I observed both a non-binary `Makefile` and a run with `ldd` absent return exit 0 and `static-check: OK`, so the gate can go GREEN without inspecting an ELF at all. That violates T01’s red-capable cgo-tainted acceptance (`docs/tasks-P0.md:19-24`). **Fix:** first verify executable ELF identity, fail if the inspection tool cannot run, and distinguish the specific static-ELF diagnostic from tool/format errors; lock both negative cases in tests alongside a dynamic fixture.

12. **[QUALITY] `Spec.Timeout` is dead configuration, so a hostile fixture can hang the suite indefinitely.** Tests default it to ten seconds, but neither `Command` nor either runner creates a context or timer (`internal/preflight/probe/probe.go:41-45,74-118`; `internal/preflight/probe/probe_linux_test.go:42-52,83-104`). A malicious or wedged target therefore blocks the go/no-go test rather than failing closed and proving cleanup. **Fix:** use `exec.CommandContext` (plus deterministic process-tree termination and wait) and add a hanging fixture that proves bounded cleanup.

13. **[QUALITY] The committed report overstates what was measured.** It publishes “10/10 PASS” and a user-namespace floor while recording `unprivileged_userns: n/a`; its transcript is cached and contains no SYSCALL case or process negative control (`docs/PROBE-REPORT-2026-09-03.md:3-15,31-38`). Given findings 1, 4 and 5, it is not valid evidence for C5’s actual-host hostile probe (`docs/HARDQ-CONSOLIDATED.md:144-146`). **Fix:** regenerate an uncached, revision-bound report only after all five capability columns and controls pass; record the exact floor-probe result and artifact hash.

14. **[OK] Several requested hardening and quality properties are present.** The bwrap argv is structurally assembled, clears inherited environment variables, creates a new session, unshares network/PID namespaces, and uses `--die-with-parent` (`internal/preflight/probe/probe.go:82-116`). Doctor output reports only whether credentials are set, not their values (`internal/preflight/doctor/doctor.go:77-97`); tests use fresh `t.TempDir` fixtures (`internal/preflight/probe/probe_linux_test.go:22-30,68-75,152-170`; `internal/preflight/doctor/doctor_test.go:15-31`); no forbidden `map[string]any` appears in the reviewed Go APIs (`CLAUDE.md:60-61`; `AGENTS.md:41-42`). These positives do not offset the false-green P0 security gates above.

VERDICT: FAIL
