1. **[UNFOLDED] The doctor floor check is functional but still not the production sandbox floor.** `FloorProbe` runs a separate blanket-`/usr` bwrap command without the synthetic memfd closure or seccomp filter (`internal/preflight/probe/probe.go:60-77`), while real launches require closure resolution, `memfd_create`, `--ro-bind-data`, a supported `GOARCH` syscall table, and kernel/bwrap seccomp support (`internal/preflight/probe/probe.go:111-190,221-299`; `internal/preflight/probe/seccomp_linux.go:48-89`). Consequently, a Linux architecture other than arm64/amd64, a host without runtime `ldd`, or a kernel/bwrap combination unable to load this filter can receive `sandbox-floor: OK` and `prerequisites-ready`, then fail every real launch. This retains the root of Codex #6 / Kilo #1: doctor can report OK on a broken prerequisite, contrary to T03 and F1 (`docs/tasks-P0.md:41-51`; `docs/HARDQ-CONSOLIDATED.md:165-172`). **Fix:** make `FloorProbe` execute a harmless target through the same `Prepare`/`Start`/`Wait` path and require the syscall-denial observation, not a weaker second profile.

2. **[UNFOLDED] The RW workdir half of Codex #8 remains caller-authorized rather than policy-authorized and remains path-racy.** `Prepare` follows symlinks with `EvalSymlinks`, accepts any resulting directory—including `/`—and later gives bwrap that path as a recursive RW bind (`internal/preflight/probe/probe.go:248-258`). There is no disposable-root/allowed-root check, ownership check, open directory handle, or `(device,inode)` recheck; a swap after `EvalSymlinks` can redirect the grant before bwrap opens it. The target is now content-copied, but the original finding covered both target and workdir. A mistaken `Spec{WorkDir: "/"}` exposes the entire host RW below `/work`, violating PRD §6 item 6 and E10’s “disposable RW workdir” (`docs/PRD.md:46-53`; `docs/ARCHITECTURE-ESSENTIALS.md:128-136`). **Fix:** accept an already-created disposable directory capability from the policy owner, verify it beneath the authorized root, and bind via a pinned directory FD or reject identity change immediately before launch; add `/`/outside-root and symlink-swap REDs.

3. **[UNFOLDED] The regenerated report is still not revision-bound.** It names the pre-fix commit `6fc4b1e...`, explicitly says the tree was dirty, and then claims it was “committed with this revision” (`docs/PROBE-REPORT-2026-09-03.md:3-8`), while reviewed HEAD is `128565b...`. The listed test names match the rewrite, so they cannot have come from the clean revision whose hash is recorded. This fails Codex #13’s requirement that evidence bind the tested artifact/revision and leaves no reproducible identity for the C5 gate (`docs/HARDQ-CONSOLIDATED.md:144-146`). **Fix:** record the exact tested tree hash (which avoids the self-referential commit-hash problem), command, dirty-state proof, and report/artifact hash from a clean tree.

4. **[NEW-ERROR] Closure resolution executes host `ldd` on the untrusted promoted target before containment.** `resolveClosure` invokes PATH-resolved `ldd` directly on `target` (`internal/preflight/probe/probe.go:139-189`). The host’s own `ldd(1)` security guidance says never to use it on an untrusted executable because some implementations/interpreters can execute code; the NEXUS target is precisely the code the sandbox is meant to distrust. It also creates a silent runtime dependency absent from doctor and the declared bwrap-only exception (`CLAUDE.md:101-104`). Finally, closure resolution occurs before the command context is created, so `Spec.Timeout` cannot stop a hanging `ldd` or bound the unbounded `os.ReadFile` copies (`internal/preflight/probe/probe.go:120-137,164-168,269-270`). **Fix:** parse `PT_INTERP`, `DT_NEEDED`, RPATH/RUNPATH and transitive libraries with `debug/elf` plus a deterministic trusted search/cache model; apply size/count/time budgets and never execute the candidate or its interpreter to discover dependencies.

5. **[NEW-ERROR] The supposedly fail-closed launcher exposes a complete boundary bypass through `Handle.Cmd`.** Although `Spec.loosen` is now unexported, `Handle` exports the mutable `*exec.Cmd`, including `Args`, `ExtraFiles`, environment and process attributes (`internal/preflight/probe/probe.go:193-200,269-299`). Any production caller can drop `--unshare-net`, `--unshare-pid` or `--seccomp`, replace the target, substitute closure/filter FDs, or restore host environment between `Prepare` and `Start`. This defeats the purpose of Codex #7 even though the named switches themselves were hidden, and violates the constitutional fail-closed boundary (`CLAUDE.md:45-50`; `AGENTS.md:30-33`). **Fix:** make the command private; expose only narrow stdout/stderr wiring and immutable PID/identity accessors, and have `Start` consume a sealed internal launch plan.

6. **[NEW-ERROR] The memfd “content pin” is writable and therefore is not hash-bound.** `memfd_create` uses flags `0`, never enables or applies seals, and the returned file remains writable (`internal/preflight/probe/memfd_linux.go:12-33`). Because the same objects are exposed through `Handle.Cmd.ExtraFiles`, a caller can rewrite a target or library after `ClosureHashes` was calculated but before bwrap consumes it; the path-swap test does not mutate the actual pinned object (`internal/preflight/probe/probe.go:120-136,271-299`; `internal/preflight/probe/probe_linux_test.go:243-268`). E10 and B4 now promise a content-pinned closure whose bytes are fixed at Prepare (`docs/ARCHITECTURE-ESSENTIALS.md:128-136`; `docs/HARDQ-CONSOLIDATED.md:75-81`). **Fix:** create memfds with `MFD_CLOEXEC|MFD_ALLOW_SEALING`, apply and verify `F_SEAL_WRITE|F_SEAL_GROW|F_SEAL_SHRINK|F_SEAL_SEAL`, hide the descriptors, and add a controlled post-Prepare memfd-write RED.

7. **[NEW-ERROR] The seccomp architecture guard fails open.** Instruction 1 jumps into the deny table only when `seccomp_data.arch` equals the Go host architecture; any other audit architecture immediately returns ALLOW (`internal/preflight/probe/seccomp_linux.go:91-107`). `Prepare` parses the target ELF but never checks its class/machine against `runtime.GOARCH` (`internal/preflight/probe/probe.go:139-151`). On an amd64 host with compat support, a promoted 32-bit ELF can therefore run under a filter that allows every syscall. The per-syscall jump fixups themselves are correct (`denyIdx - i - 1` lands exactly on the trailing ERRNO instruction), but the preceding architecture branch invalidates the fail-closed claim. **Fix:** return KILL/ERRNO on every unexpected audit architecture and reject a target ELF whose machine/class is not the supported native ABI; add a unit-level cBPF interpreter/fixup test and a compat-ELF RED where available.

8. **[NEW-ERROR] Every prepared launch leaks the seccomp-filter FD, and unsuccessful direct `Start` has no owned cleanup path.** The filter file is appended to `cmd.ExtraFiles` but not to `Handle.closers`; `Wait` closes only closure memfds (`internal/preflight/probe/probe.go:193-219,280-299`). A long-lived assistant therefore retains roughly one descriptor per command until nondeterministic GC, eventually reaching `EMFILE`. Moreover, callers using `Prepare`/`Start` directly must know to call `Wait` even after `Start` fails, and there is no `Close`/abort method. **Fix:** make the handle own every FD and close all of them exactly once on every Prepare/Start/Wait/Kill failure path; add a repeated-launch `/proc/self/fd` stability test.

9. **[OK] The central T02 false-green folds are otherwise real.** The production `Run → Prepare → Start → Wait` path is used without argv rewriting (`internal/preflight/probe/probe.go:221-321`; `internal/preflight/probe/probe_linux_test.go:43-49`); `/usr/bin/id` is now the undeclared-child regression and passed as denied (`internal/preflight/probe/probe_linux_test.go:232-241`); `/etc` grants are gone; and FS/network/syscall negative controls use test-owned resources (`internal/preflight/probe/probe_linux_test.go:96-128,145-209`). The shadow literal has a host-existence precondition and the paired readable-canary mutation supplies causal FS evidence, so Kilo’s suggested EACCES-only oracle is unnecessary: invisibility/ENOENT is a valid stronger result under the newly approved synthetic closure (`internal/preflight/probe/probe_linux_test.go:81-128`; `docs/HARDQ-CONSOLIDATED.md:75-88`).

10. **[OK] PROC_TREE and timeout folds now exercise the intended production behavior.** The suite records exact host `(pid,starttime)` descendant identities, proves the oracle nonempty before kill, kills through `Handle.Kill`, and verifies those identities disappear; the loosened PID-namespace case kills only the leader and requires owned descendants to survive before cleanup (`internal/preflight/probe/probe_linux_test.go:270-390`). This removes the `pgrep` dependency, group-kill confounder and positional argv mutation from Codex #5, Kilo #2/#5 and Agy #3-#5. The hanging-target case also returns through the configured command timeout (`internal/preflight/probe/probe_linux_test.go:392-414`), subject to the pre-`CommandContext` resolver gap in finding 4.
