[HIGH] `internal/schedule/schedule.go:342`, `cmd/nexus/main.go:126` — Firing and obligation admission are separated by an unrecoverable crash window. `Sweep` atomically commits `occurrence_fired + run.created + run.admitted`, which permanently flips `fired=1`; only afterward does an in-memory callback call `MarkDue`, and its error is discarded. A crash after the batch commit, a callback error, or shutdown at that boundary leaves the obligation forever `SCHEDULED`; later sweeps exclude it because the schedule is already fired. This breaks PRD §6.3 and HARDQ B1/B7. Fix by putting the obligation `DUE/DELIVERY_PENDING` transition in the same named transaction recipe, or by durably recording callback work and replaying it until acknowledged.

[HIGH] `internal/obligation/obligation.go:524` — Completion has both a TOCTOU false-PASS and a mutable-artifact false-FAIL. `MarkTaskDone` reads and hashes the file, then separately appends DONE; another task or process can change the file between those operations, so DONE can commit for content that no longer exists. Conversely, after task A records hash(A), a legitimate task B appends a line and produces hash(A+B), making A impossible to complete even though A's line is present.
