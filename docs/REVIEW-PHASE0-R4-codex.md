1. **[UNFOLDED] Legacy `DT_RPATH` is read but its required transitive inheritance is not implemented.** `elfDeps` returns only the current referrer's own RUNPATH or RPATH, and child queue nodes receive only that child's paths (`internal/preflight/probe/probe.go:184-200,292-343`). Linux loader semantics differ: RUNPATH applies only to direct children, while RPATH applies through the dependency tree. A fresh executable with main `RPATH=$ORIGIN/../a:$ORIGIN/../b`, direct `libnexusr4a.so`, and transitive `libnexusr4b.so` ran successfully under the host loader (`host_rc=0`), but `resolveClosure` failed with `cannot resolve library "libnexusr4b.so"`. The committed tests cover expansion and a root RUNPATH binary only (`internal/preflight/probe/probe_linux_test.go:571-617`), so they cannot detect this fold failure. Carry inherited RPATH separately through each queue node, suppress it according to RUNPATH precedence, and add this old-dtags transitive fixture.

2. **[UNFOLDED] The new “pre-allocation” budgets remain bypassable because validation and allocation do not share an opened file, and the queue cap is checked after allocation.** `add` performs path-based `os.Stat`, then independently reopens the path with `os.ReadFile` (`internal/preflight/probe/probe.go:225-256`). A regular file can be replaced or grown between those operations, so `ReadFile` can allocate beyond the stat-approved size before the post-read aggregate check. Target parsing, copying and dependency parsing also reopen the same path at separate times (`internal/preflight/probe/probe.go:260-299,332-340`), so the resolved metadata need not describe the pinned bytes. Separately, all root dependencies are appended before `len(queue)` is checked, and each complete `ImportedLibraries` result is appended before the next iteration checks the cap (`internal/preflight/probe/probe.go:295-313,336-343`). Open once, `fstat` and bounded-read that same descriptor, and parse/hash/pin the same bytes; enforce `len(queue)+len(new)` before append (or parse dependency entries under an explicit metadata budget). Add swap/grow-between-check-and-read and over-cap dependency-table REDs.

3. **[NEW-ERROR] The workdir “allowlist” can be widened to an arbitrary host tree by ambient environment.** `allowedWorkRoots` trusts `os.TempDir()` (which is derived from `TMPDIR` on Unix) and raw `XDG_RUNTIME_DIR` without canonicalizing or validating either root (`internal/preflight/probe/probe.go:348-378`). With `XDG_RUNTIME_DIR=/home/matej`, the guard accepted the existing mode-0700 `/home/matej/.ssh`; an untrusted target would then receive that sensitive tree recursively RW at `/work`. Candidate ownership and `0o022` checks do not restore the missing authority boundary. Canonicalize each root and admit it only if it satisfies a fixed policy: a current-user-owned private runtime root, or a verified system sticky temp root; ignore/refuse malformed ambient roots. Add hostile `TMPDIR`/`XDG_RUNTIME_DIR`, symlinked-root and unsafe-parent REDs. Candidate symlinks themselves are correctly canonicalized and fail closed.
