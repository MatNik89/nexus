1. **[NEW-ERROR] The new integrity chain does not authenticate the complete `JournalEvent`, and it is not enforced on recovery or replay.** Append hashes only `prevHash || envelope` (`internal/kernel/journal/journal.go:181-196`), so `journal_offset`, `event_id`, `run_id`, `sequence`, `redaction_policy_version`, and `sealed_payload_ref` can be changed without invalidating `integrity_hash`. `VerifyChain` repeats that incomplete formula (`internal/kernel/journal/journal.go:264-290`), while `Open` trusts only the last row's stored hash without verifying the chain (`internal/kernel/journal/journal.go:99-119`) and `Replay` never invokes verification (`internal/kernel/journal/journal.go:228-262`). A modified earlier row or metadata column is therefore accepted during normal startup/replay unless an optional caller remembers to run `VerifyChain`. The test mutates only `envelope`, the sole field the implementation hashes (`internal/kernel/journal/journal_test.go:225-243`), so it is implementation-derived. **Fix:** hash a canonical encoding of every journal field except `integrity_hash`, verify offsets/denormalized columns against the envelope, and fail `Open` (or mandatory replay admission) on any chain failure; add one mutation per metadata class.

2. **[NEW-ERROR] Whole-record redaction creates two different “canonical” events and still permits secret persistence.** `env` is constructed before the full-record redaction; only the serialized `raw` copy is redacted, yet `Append` returns the original `env` (`internal/kernel/journal/journal.go:173-207`). Thus the test's secret-bearing `EventType` is absent from the DB but remains in the returned event, from which synchronous projections can leak it. Worse, denormalized `event_id` and `run_id` columns are populated from the unredacted `env` (`internal/kernel/journal/journal.go:191-197`), so a known secret in either valid ID reaches SQLite. Redacting structural fields can also make stored JSON semantically differ from uniqueness/profile keys or even become invalid, and the post-redaction bytes are never re-parsed. The RED checks only DB/WAL bytes for a secret in `EventType`, not the returned event or indexed columns (`internal/kernel/journal/journal_test.go:146-162`). **Fix:** classify/reject known secrets in structural/indexed fields before validation, redact payload/content semantically, construct one final canonical envelope, and use that same value for return, columns, hashing, and replay.

3. **[UNFOLDED] Round-1 #9's physical profile binding is only process-memory binding.** `Open(path, profile, ...)` never records or checks the profile inside the database (`internal/kernel/journal/journal.go:68-120`). Reopening an existing work DB as `private` therefore succeeds and permits private events into the same physical file; two handles can also create two append actors for one DB, violating HARDQ B3/B7. Because each actor caches `lastOffset/lastHash`, the loser of a concurrent write remains stale and repeatedly collides instead of recovering (`internal/kernel/journal/journal.go:123-143`). `TestProfileMismatchRejected` checks only one handle's in-memory comparison (`internal/kernel/journal/journal_test.go:83-91`); the requested second-opener RED from round-1 #16 is still absent. **Fix:** create and transactionally verify immutable DB metadata containing the bound profile, reject a mismatched reopen, and enforce one writer/lease per DB (the later daemon/UDS layer may own cross-process exclusion, but this storage owner must at least detect violation).

4. **[UNFOLDED] Round-1 #5 preserves unknown fields only as an ignored sidecar, so the normal wire round-trip still loses them.** `ParseEnvelope` copies input to `Envelope.Wire`, but `Wire` is tagged `json:"-"` (`internal/kernel/contracts/contracts.go:21-52`; `internal/kernel/contracts/schema.go:58-80`). Calling `json.Marshal` on the admitted envelope—the normal contract wire operation—drops every unknown field. The new test asserts merely that `back.Wire` contains the field and never reserializes it (`internal/kernel/contracts/contracts_test.go:354-369`). **Fix:** make the canonical marshal path merge preserved `json.RawMessage` fields with updated known fields, or expose a mandatory lossless wire method and prevent plain `json.Marshal(Envelope)` from silently producing a lossy representation; add parse→marshal→parse preservation RED.

5. **[UNFOLDED] Round-1 #10/#11 redaction remains pre-validation-incomplete and byte-spelling-dependent.** Only payload bytes are redacted before `NewEnvelope`; full-record redaction is after validation (`internal/kernel/journal/journal.go:146-184`). Unknown-schema errors still echo `SchemaID` (`internal/kernel/contracts/contracts.go:86-101`; `internal/kernel/contracts/schema.go:27-36`), so a known secret used there reaches an error sink. `KnownRefs` adds only the raw value and Go's preferred JSON escape spelling (`internal/security/redact/redact.go:30-68`); semantically identical valid JSON such as `"s\u0065cret"` bypasses a known value `secret`. The escaped-secret RED covers quotes/backslashes in Go's one encoding, not alternate Unicode escapes (`internal/security/redact/redact_test.go:41-52`). **Fix:** never echo discriminator values, and redact decoded JSON string values (or a token stream) rather than enumerating byte spellings; test `\u` case/escape variants and validation-error paths.

6. **[NEW-ERROR] Recursive validation validates normalized copies but returns the original nested values.** `ContextBlock.Validate` rebuilds and discards a normalized block (`internal/kernel/contracts/contracts.go:222-233`); `NewMessage` then returns the caller's original slice (`internal/kernel/contracts/contracts.go:243-265`), and `NewToolResult` does the same for output blocks (`internal/kernel/contracts/contracts.go:380-413`). A valid block with a non-UTC `ObservedAt` therefore passes validation but remains non-UTC inside the newly constructed Message/ToolResult, contradicting the UTC fold and the constructors' canonicalization promise. Caller-owned slices/pointers also remain aliased and can be mutated after admission. **Fix:** return/copy the normalized nested values (including owned slices/pointers), or make validation reject non-canonical input; add a nested non-UTC and post-construction mutation RED.

7. **[UNFOLDED] Enum methods close typed enum fields, but envelope schema admission still accepts unknown event/payload discriminators.** The new JSON methods correctly reject numeric/unknown values when a consumer unmarshals into an enum (`internal/kernel/contracts/enums.go:279-297,373-511`). However `Envelope.EventType`/`ActorType` remain arbitrary non-empty strings, and `Payload` is admitted as any syntactically valid `json.RawMessage` with no event-type/schema-specific validation (`internal/kernel/contracts/contracts.go:26-46,79-138`). `Journal.Append` therefore durably commits an unknown event discriminator or a payload containing an invalid/numeric enum before any typed consumer sees it, contrary to E3 and P0.3's `validate schema`-before-append ordering. This is the payload path described in Codex/Kilo round-1 enum findings, not a complaint about the now-correct enum methods. **Fix:** bind each closed `event_type` to a typed payload validator at journal admission and reject unknown event/actor discriminators before persistence; add Envelope-level numeric/unknown payload REDs.
