## New defects introduced by the fold

14. **[NEW-ERROR] `QueryProjection` is not SELECT-only: a multi-statement query can mutate projection state outside the journal.** It checks only that the complete string starts with `select`, then hands the whole string to modernc SQLite (`internal/kernel/journal/projection.go:180-192`). A safe probe against HEAD executed `SELECT v FROM probe_rows; DELETE FROM probe_rows; SELECT v FROM probe_rows`; the call returned no error and the subsequent count was zero. This lets any holder of the advertised read seam alter `mem_facts` (including forging profile stamps) without a canonical event, violating P0.3. The old lexical-guard comment also says T18 is the trigger for replacing that ceiling, but T18 retained it (`internal/kernel/journal/projection.go:15-32`). Fix: expose a genuinely read-only, single-statement boundary—prefer fixed typed projection queries; otherwise enforce one prepared statement and SQLite read-only authorization. Add an ablation that proves projection rows cannot be inserted/updated/deleted through this seam.

15. **[NEW-ERROR] Moving facts into the redacted journal silently changes exact-approved memory bytes and makes the receipt disagree with stored state.** `Journal.appendOne` redacts payload bytes before payload validation and projection application (`internal/kernel/journal/journal.go:381-393,429-437`). `memory_remember` then hashes the original content in its commit receipt and success text (`internal/memory/tools.go:84-93`). A safe probe approved `remember SECRET-CANARY byte exactly`; the actual row contained `remember [REDACTED:KEY] byte exactly`. This contradicts B8's exact preview/bytes-lossless rule and produces a receipt for bytes that did not commit. Fix: reject a known-secret memory write before approval/append for P0, or use the authorized sealed-reference design; never silently rewrite the approved fact.

16. **[NEW-ERROR] The mandatory production memory RED is flaky because it does not join the old daemon before reusing its socket path.** `runSession` cancels the daemon on return but never waits for `Serve` to finish (`cmd/nexus/main_test.go:131-155`), then the next session starts another daemon on the same UDS path. In 20 repetitions it failed with `connection reset by peer`; in a focused 50-run command it connected to the old daemon after its journal had closed. A flaky phase gate can both reject good code and hide ordering bugs. Fix: capture the Serve result, cancel, and wait for goroutine termination before closing the journal or starting the next incarnation.

17. **[NEW-ERROR] Tool-enabled provider prompts are nondeterministic.** `Plan` ranges directly over the sealed-spec map when rendering the available-tool list (`internal/llm/planner/planner.go:192-198`). Go map iteration order is unspecified, so identical inputs can produce byte-different system prompts and potentially different plans. This defeats the repository's deterministic-fixture discipline and makes provider caching/replay harder to reason about. Fix: sort tool IDs before rendering and add a repeated byte-equality assertion.

The strict JSON tool/prose boundary itself survived adversarial inspection: ignored model fields cannot override sealed metadata, an unknown tool ID errors, and malformed/trailing tool-shaped output reaches no effect. The two declared ceilings—buffered Chat with tools and fail-closed `NEEDS_APPROVAL` until T24—are acceptable in their stated scope.
