1. [UNFOLDED] R2 #2 — `DeliveryReceipt` is now a durable payload, but `AckGesture` is not a durable artifact. `MarkAcked` uses the caller-supplied source only to construct an in-memory checker bundle, then appends `EvAcked` through `occEvent`, whose payload contains only `occurrence_id` and whose actor is the obligation system (`internal/obligation/obligation.go:646-652,685-722`). Replay therefore cannot establish who acknowledged the occurrence. Worse, a producer can append a plain `EvAcked` after delivery; the validator and projection require no gesture (`:137-161,318-323`). The declared T22 ceiling reasonably defers transport authentication of receipt/gesture identities, but it does not justify discarding the gesture or permitting the canonical transition without it. Persist an ack payload carrying its source/identity and make projection admission require it; T22 can later authenticate that source.

2. [UNFOLDED] R2 #5 — the new intent CAS does not prevent concurrent execution. If call A has committed its claim but has not yet written the file, call B reads the existing `intent_op`, checks the marker before A writes it, and then dispatches the handler under A's stored operation (`internal/obligation/obligation.go:739-782`). Both handlers subsequently append the same note; `fileNoteMu` serializes the writes but does not deduplicate them. `TestProjectionEnforcesExecutionProtocol` submits two sequential intent events; it never runs two production executions across this claim→effect window (`obligation_test.go:388-434`). A claim needs a live-executor lease/ownership rule or a recovery-only takeover after the original execution is definitively absent—not immediate “intent exists + marker absent = safe to execute.”

3. [OK] R2 #10 — `Run` now gives its interval to `SetSweepInterval` and uses the resulting same field for both `Sweep`'s OVERDUE classification and the ticker (`internal/schedule/schedule.go:381-383,461-484`). Non-positive input consistently retains the 30-second default.

4. [UNFOLDED] R2 #11 — parsing improved, but observability is still not operationally honest. `Run` stores failures only in process-local `lastErr`; the sole consumer of `Health()` is a test, not `runDaemon` or doctor (`internal/schedule/schedule.go:465-496`; repository call-site sweep finds only `cmd/nexus/main_test.go:247`). If the first mirror write fails, the daemon continues silently and doctor sees ENOENT as “no occurrences fired yet”/OK (`internal/preflight/doctor/doctor.go:119-142`). Thus the exact write-failure scenario from R2 still reports healthy. Wire scheduler failures to an owned durable/logged health surface, or give doctor enough authoritative state to distinguish never-fired from a missing mirror. Add REDs for mirror-write failure, malformed data, and unreadable data; none currently exist in doctor/schedule tests.

5. [UNFOLDED] R2 #13 — the per-kind validator is enforced only by `Manager.CreateTask`, not by canonical journal admission. `Events(taskKinds ...string)` receives names only, and its `EvCreated` validator checks ID/kind but never invokes `ValidateFileNoteParams` (`internal/obligation/obligation.go:128-160`). A forged or buggy in-process producer can therefore append `kind:"file_note", task_params:"not-json"`; the projection accepts an irrecoverably unexecutable OPEN task. Build `Events` from the sealed kind→validator registry (or otherwise validate kind-specific payloads at the journal boundary), rather than duplicating only its names.

6. [UNFOLDED] R2 #14 — the SIGKILL test is real-process but not causal at the named boundary. The parent sleeps arbitrary 20/35/50/65 ms, ignores both `Kill` and `Wait` results, and never asserts that the child created or fired even one occurrence (`internal/schedule/schedule_test.go:467-511`). Opening an empty/new journal makes `for run := range occ` vacuously pass. There is also no barrier placing SIGKILL between recipe members, so replacing the batch with fast sequential appends can survive all four runs. Use a child/parent barrier at the append recipe boundary, prove the child reached it, assert SIGKILL termination, and require non-empty pre/post workload plus the BOTH-or-NEITHER oracle.

9. [UNFOLDED] R2 #17 — normal `CreateTask` now seals IDs to `[A-Za-z0-9_-]{1,64}` and notes to one line, which prevents the reported marker aliases. Canonical admission does not enforce either rule: `Events` still accepts any non-empty ID and any params for a registered kind (`internal/obligation/obligation.go:147-160`), while projection `Apply` inserts them unchanged (`:275-293`). A forged producer can therefore reintroduce `id:"a] b"` or a multiline note and later exploit the same marker ambiguity. The seal belongs at the event admission boundary as well as the facade.

10. [UNFOLDED] R2 #18 — CAS and operation matching close several malformed sequences, but the projection is not airtight against forged producers. A producer may append a valid intent and then a matching `EvTaskExecuted` with arbitrary `expected_path`/`marker_line`; projection accepts it because it checks only operation equality/non-empty marker (`internal/obligation/obligation.go:330-362`). It may then append `EvTaskDone`, which checks only that the row has a non-empty marker and never that the checker observed the file (`:363-399`). The added RED rejects no-claim, wrong-operation, and overwrite cases, but explicitly accepts the exact forged matching-claim shape (`obligation_test.go:408-427`) and never tests direct DONE after it. Bind attestation to the task's canonical handler-specific expectation and carry checker evidence/identity into the DONE event so projection admission can reject a producer that skipped verification.
