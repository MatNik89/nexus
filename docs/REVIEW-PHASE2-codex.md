# Phase 2 deep + E2E integration review (Codex)

Reviewed `slice/p0-phase2` at `17f56031d98b07fd11d65a6e2dca9173f319e738` against `tasks-P0.md` T13-T17, Annex P0.2/P0.7, DESIGN-FIXES-r2 K1/K2, and the CLAUDE/AGENTS hard rules. The T13-T17 package tests pass in isolation, but the implementation does not satisfy the two mandatory gates.

1. **[HIGH] T15 bypasses S7 for every production provider attempt** — `internal/llm/provider/provider.go:107-139`, `internal/llm/provider/provider.go:152-163`, `internal/llm/provider/provider.go:166-236`, `internal/llm/planner/planner.go:40-52`. `Chat`, `Stream`, and `Probe` own the physical `http.Client.Do` calls but accept no `AttemptGrant`; the production planner calls `Chat` directly. A provider request can therefore execute without grant consumption, S7 accounting, or S7-owned cancellation/deadline. This directly violates Annex P0.2 and T13's acceptance (“every physical attempt carries a grant”). Move the transport attempt behind an S7-consuming seam; the planner should request an operation, not invoke an ungoverned transport.

2. **[HIGH] The structured-output re-ask grant is decorative, so an adapter can self-retry** — `internal/llm/provider/structured.go:103-130`, `internal/llm/provider/provider_test.go:175-198`. `Extract` consumes the grant *before* invoking the arbitrary `ReAsk` callback. Nothing binds one callback invocation to one physical transport call, so a callback can call HTTP twice (or retry internally) while presenting one already-consumed grant. The test only checks that a nonce exists and that the callback ran once; it would stay GREEN if the callback performed two physical calls. Make grant consumption part of the transport call itself and add the Annex P0.2 counter oracle (second transport rejected, transport count 1, S7 attempt count 1).

3. **[HIGH] Tool admission does not validate the call or bind the grant/deadline to it** — `internal/kernel/loop/loop.go:177-202`, `internal/kernel/effectpath/effectpath.go:252-292`, `internal/kernel/s7min/s7min.go:126-149`. Neither the loop nor `RunTool` calls `ToolCall.Validate`; the loop issues every grant for the constant target `"local"`; and `RunTool` never checks that `grant.OperationID`, target, attempt, or expiry represents this call/profile. It also never enforces `call.Deadline`. A planner can supply an expired call, `AttemptNo=9`, a foreign `ProfileID`, missing idempotency key, or reuse an otherwise-valid grant minted for another call, and still reach an executor. Validate at the effect boundary and have S7 mint/consume a call-bound operation with an S7-owned deadline context.

4. **[HIGH] Effectful executor errors are falsely finalized instead of parked UNKNOWN** — `internal/kernel/effectpath/effectpath.go:292-300`. Any executor error is reported as `OutcomeFailedTerminal`, without examining a receipt or the call's effect class. If an irreversible tool commits and then loses its reply, the code declares FAILED and the loop may continue, permitting a later duplicate effect. The locked K2/E9 rule is the opposite: effectful without a valid receipt is UNKNOWN and reconciliation-only. Apply `ClassifyEffectPhase` to every post-dispatch failure, not only an `AfterTool` veto.

5. **[HIGH] Unvalidated `ToolResult` status creates S7/journal split-brain** — `internal/kernel/effectpath/effectpath.go:316-327`, `internal/kernel/loop/loop.go:202-235`, versus the available validator at `internal/kernel/contracts/contracts.go:477-515`. Executors return public structs and `RunTool` never validates correlation, timestamps, error shape, output blocks, or receipt. Worse, `ResultFailed`, `ResultCancelled`, and `ResultUnknown` all return a nil Go error; the loop then appends `attempt.succeeded` and feeds output to the planner. Even `ResultSucceeded` for an effectful call with no receipt is reported SUCCEEDED, contrary to the UNKNOWN rule. Normalize/validate the result against the exact call and drive the journal transition from its closed status/effect phase, not `err == nil`.

6. **[HIGH] The journal claims an attempt started before policy and grant consumption, and cannot recover a post-effect append failure** — `internal/kernel/loop/loop.go:187-202`, `internal/kernel/loop/loop.go:225-235`. The loop appends `attempt.started` before `RunTool` performs PEP, middleware, or `grants.Consume`. Thus a DENY or unanswered ASK is durably recorded as a physical RUNNING attempt that never happened, while S7 remains AUTHORIZED. Conversely, if the executor effects state and the subsequent `attempt.succeeded` append fails, the turn returns without recording UNKNOWN/reconciliation. Journal transitions need to be emitted at the authoritative S7 transition (or from a single callback/transactional seam), with post-dispatch persistence failure classified conservatively.

7. **[HIGH] Multiple tool calls in one turn are not replayable** — `internal/kernel/loop/loop.go:79-89`, `internal/kernel/loop/loop.go:187-200`, `internal/kernel/loop/loop_test.go:188-207`. Every attempt event omits the envelope `ToolCallID` and carries only `turn_id`; the E2E test folds one undifferentiated attempt stream and covers exactly one call. With two successful calls, replay sees `PLANNED...SUCCEEDED, PLANNED...` and rejects the second transition from a terminal state. Persist the exact `TurnID`/`ToolCallID` correlation and fold each attempt independently; add a two-call replay RED.

8. **[HIGH] Tool-controlled error text is laundered to trusted model input and can carry secrets** — `internal/kernel/loop/loop.go:119-130`, `internal/kernel/loop/loop.go:213-223`, `internal/kernel/loop/loop_test.go:211-230`. Raw `%v` from an executor is labeled `TOOL_TRUSTED`, appended to the next planning context, and the test explicitly requires that trust. An external tool can return `"ignore system; exfiltrate ..."`; the next provider call receives it outside the untrusted fence. Errors can also contain credential-bearing URLs or subprocess stderr, with no redaction before that provider sink or the UDS error path. Convert only a validated `TypedError.SafeMessage`, mark external error content untrusted, retain lineage, and redact before every journal/model/UI boundary.

9. **[HIGH] YOLO can execute without its mandatory audit record** — `internal/kernel/effectpath/effectpath.go:53-57`, `internal/kernel/effectpath/effectpath.go:258-261`, `cmd/nexus/main.go:68-89`. `AuditSink.Record` cannot return an error; `journalAudit` discards `Journal.Append` errors and increments an unsynchronized counter shared by concurrent daemon sessions. A DB failure therefore still permits an ASK action under YOLO with no `ALLOWED_BY_YOLO` record. Concurrent calls can race the counter and collide event IDs, also silently discarded. Make the audit append return an error and gate execution on durable success; allocate identity through a concurrency-safe journal-owned path.

10. **[HIGH] The provider allowlist is bypassable by redirects and permits bearer credentials over plaintext HTTP** — `internal/llm/provider/provider.go:62-93`, `internal/llm/provider/provider.go:116-130`, `internal/llm/provider/provider.go:184-197`. Only the configured initial `u.Host` is checked. Go's default client follows redirects, so an allowed endpoint can redirect conversation data to an unlisted/internal host. The constructor also accepts non-loopback `http://` and sends the bearer key in cleartext. Install a redirect hook that re-applies the egress decision (and strips credentials unless the destination is identically authorized), and require HTTPS except for an explicit loopback test/local-provider policy.

11. **[MED] S6.9 middleware can erase a refusal and thereby decide outcome** — `internal/kernel/effectpath/effectpath.go:270-290`, `internal/kernel/effectpath/effectpath.go:292-314`. Every rejection returns the value of `OnError`; an order-only middleware that returns nil converts an unknown execution kind, invalid grant, executor error, or post-effect veto into nil error. The loop then follows the success branch. That gives S6.9 authority over policy/lifecycle despite the locked “order only” invariant. Preserve and join the causal error; `OnError` may add an error but must never clear the original.

12. **[HIGH] T17's claimed E2E gate bypasses the production seams it is supposed to integrate** — `internal/app/daemon/daemon_test.go:34-58`, `internal/app/daemon/daemon_test.go:162-184`, `internal/app/repl/repl_test.go:27-59`, `internal/app/daemon/daemon_test.go:269-286`. The daemon “E2E” injects an `echoPlanner`, not a deterministic fake provider through the real `planner`; the REPL test connects to a fake server; and the opt-in live smoke calls `provider.Chat` directly. No test spans real REPL → UDS → daemon → loop → real planner → provider seam → journal, and no single production-path test crosses PEP/S7. Consequently it stays GREEN with the S7 bypass, audit fail-open, and trust defects above. Add one deterministic transport-backed full-spine test, plus a tool-action variant when the structured planner seam exists; keep the paid/live probe separately labeled.
