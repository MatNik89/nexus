# PHASE-1A verification round 3 — Codex

Scope: `slice/p0-phase1` at `1c5c8a56aef9d19d9cdbb0cab1c50814e4995f32`, restricted to the eight round-2 folds and defects introduced by that commit.

- `go test -count=20 ./internal/kernel/journal ./internal/kernel/contracts ./internal/security/redact` — PASS.
- `go test -race -count=1 ./internal/kernel/journal ./internal/kernel/contracts ./internal/security/redact` — not runnable on this host: ThreadSanitizer aborts before tests with `unsupported VMA range` (proof ceiling, not a code finding).

1. **[UNFOLDED] The full-record hash still does not unambiguously authenticate the full record.** `chainInput` joins attacker-influenceable text fields with bare `|` delimiters, although IDs may contain `|`, and encodes both `sealed_payload_ref = NULL` and `sealed_payload_ref = ""` as the same empty string (`internal/kernel/journal/journal.go:48-58`; `internal/kernel/contracts/ids.go:28-33`). For example, the heads for `(event_id="a", run_id="b|c")` and `(event_id="a|b", run_id="c")` are identical. `verifyChainFull` hashes that ambiguous encoding without parsing the envelope or checking its denormalized columns (`journal.go:415-446`), so such a metadata rewrite can pass `Open`; `Replay` detects the denormalized mismatch only later. The new RED mutates `sealed_payload_ref` to a non-empty value and therefore misses the NULL/empty collision (`journal_test.go:363-393`). Use a canonical length-prefixed/binary encoding that preserves nullability, and make the open-time walk perform the same envelope/column consistency checks as replay.

2. **[UNFOLDED] Structural-secret rejection is incomplete and optional.** `structuralFields` omits `ParentEventID`, so a known secret embedded in that valid ID is serialized and persisted (`internal/kernel/journal/journal.go:245-266,312-329`). More fundamentally, rejection runs only when the supplied `redact.Redactor` also happens to implement the separate optional `Toucher` interface (`journal.go:279-287`; `internal/security/redact/redact.go:17-20,165-168`); `Open` accepts a redactor that knows/replaces secrets but cannot preflight them. The sole RED covers only `ActorID` with `KnownRefs` (`journal_test.go:168-186`). Make structural inspection part of the required redactor contract (with `None` explicitly reporting no matches), enumerate every string-bearing non-payload field including `ParentEventID`, and use a table-driven field RED.

3. **[UNFOLDED] The live-writer lease does not enforce one writer per database.** A stored lease is rejected only when `oldPid != pid`; therefore two `Open` calls in the same process both succeed and start independent append actors over the same file (`internal/kernel/journal/journal.go:185-205,210-222`). The test explicitly avoids this real case, closes the owner, manually plants the parent PID, and calls that a “second live opener” (`journal_test.go:263-285`). That is a false-green for round-2 #3, which named two handles as the failure scenario. The lease is also never released by `Close` (`journal.go:455-463`) and is committed before chain verification (`journal.go:201-219`): a failed open can leave a live-PID lease despite never starting an actor, blocking another process until this process exits. Use an OS/file lock or a per-handle nonce plus atomic ownership/release; verify the chain before publishing ownership or conditionally release the exact acquired token on every failure and `Close`. Add an actual simultaneous same-process two-handle RED and a failed-open/no-stale-lease RED.

4. **[NEW-ERROR] The supposedly closed event registry remains caller-mutable after `Open`.** `Open` stores the caller's map directly (`internal/kernel/journal/journal.go:122,210-212`) and the actor reads it on every append (`journal.go:273-277`). The caller can add an unreviewed event type or replace/remove its validator after admission; concurrent mutation can also trigger Go's fatal concurrent-map read/write failure. This defeats the closed-set property added for fold 7 even though the static unknown-type and validator tests pass. Validate and defensively copy the registry during `Open`, then retain only the private copy; add post-open mutation and concurrent-mutation REDs.

5. **[NEW-ERROR] `Envelope.MarshalJSON` can resurrect a stale known optional field from `Wire`.** The merge overwrites only keys emitted by the current known struct (`internal/kernel/contracts/contracts.go:58-84`). Because `turn_id`, `tool_call_id`, `parent_event_id`, `tenant_id`, and `idempotency_key` use `omitempty`, clearing one after parsing omits it from `kn` but leaves the original value in `orig`; marshaling therefore silently restores the old field. The new round-trip RED never changes a known field (`contracts_test.go:355-386`). Start from unknown fields only (or delete all known keys from the preserved map before inserting the current encoding), and add parsed-envelope mutate/clear REDs. Locally built envelopes (`Wire == nil`) do marshal through the non-recursive shadow correctly.

6. **[OK] Decoded-JSON redaction and the targeted no-echo schema error are folded.** String values and keys are decoded before matching, covering `\\u` spellings, and non-JSON retains the raw replacement fallback (`internal/security/redact/redact.go:52-146`; `redact_test.go:41-62`). `UnknownSchemaError.Error` and constructor rejection no longer echo the caller-controlled schema ID while the typed error still preserves raw input (`internal/kernel/contracts/schema.go:27-39`; `contracts.go:134-141`).

7. **[NEW-ERROR] The decoded JSON walker creates an unbounded, superlinear admission cost.** At every nested object/array, `redactJSONValue` unmarshals the entire remaining subtree and then recursively unmarshals each child (`internal/security/redact/redact.go:61-125`), so a deeply nested payload is reparsed at every level (quadratic work and large transient allocation). There is no payload-size/depth budget in `Envelope` or `Journal.Append` (`internal/kernel/contracts/contracts.go:172-176`; `internal/kernel/journal/journal.go:288-297`). A single valid deeply nested channel payload can monopolize the sole append actor before any durable admission. Replace this with a single-pass token/stream transformation and enforce explicit byte/depth budgets before recursive allocation; add near-limit and over-limit REDs.

8. **[OK] Nested `ContextBlock` values are now normalized and copied for `Message` and `ToolResult`.** `Normalized` owns content/ref pointers and lineage and routes expiry through the UTC-normalizing constructor; both parent constructors build fresh normalized slices (`internal/kernel/contracts/contracts.go:273-303,313-340,453-491`). The mutation/UTC RED exercises the Message path (`contracts_test.go:388-413`).

9. **[OK] Actor admission is closed and event admission has a real typed-validator seam.** `ActorType` now uses closed string JSON encoding (`internal/kernel/contracts/enums.go:231-247,329,528-540`), and `Journal.Append` rejects event types absent from its registry and runs a registered validator after semantic redaction but before persistence (`internal/kernel/journal/journal.go:273-297`; `journal_test.go:288-330`). Finding 4 above prevents calling the registry itself immutable/closed after `Open`.

10. **[UNFOLDED] The commit-failure RED is useful, but the admission-definitive RED remains vacuous.** `testFailCommit` deterministically forces transaction rollback before `Commit` and proves the next offset/sequence remains 1 (`internal/kernel/journal/journal.go:323-339`; `journal_test.go:332-349`). However `TestCancelledContextAfterAdmissionStillDefinitive` still cancels before calling `Append` and explicitly accepts either branch (`journal_test.go:188-215`); it has no actor-admission barrier and cannot force cancellation into the post-admission/pre-result window. An implementation that incorrectly selected `ctx.Done()` after admission could still pass. Retain the production `Append` path, pause the actor after receiving the request but before reply, cancel there, and require the definitive committed result.

11. **[OK] The remaining persistence portions of folds 1 and 3 work as claimed.** Profile identity is stored in `journal_meta` and a different-profile reopen is rejected (`internal/kernel/journal/journal.go:156-176`; `journal_test.go:252-261`). The chain is walked on `Open` and on every `Replay`, and the changed REDs independently mutate envelope, event/run IDs, sequence, policy version, and a non-empty sealed reference (`journal.go:362-446`; `journal_test.go:351-414`). These improvements do not close findings 1 and 3.
