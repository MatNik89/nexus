# PHASE-1 batch review — T07–T12 (Codex)

Scope: `slice/p0-phase1` at `e94e97e5381d7773fe6e710eaeb0069bc2f27b41` (clean worktree before this report). Sources: `tasks-P0.md` T07–T12, HARDQ B5/B7/B9/C3, Annex P0.1/P0.3/P0.5/P0.6, Essentials E5/E7/E11/E13, and `CLAUDE.md`.

1. [BREAK] **T12 does not enforce `checker != worker`; it grades unauthenticated caller assertions, not artifacts.** `AcceptanceContract` has no assigned-worker identity, `Evidence` has no producer/checker identity, contract ID, execution receipt, or revision binding, and `Grade` accepts the values directly (`internal/kernel/checker/checker.go:52-64,118-143`). A worker can construct `{Exit: Code:0}` and an arbitrary matching hash string and grade its own work PASS without running a command or hashing a file. This violates T12's explicit “Checker != worker principal” (`docs/tasks-P0.md:140-146`), E13's artifact grading (`docs/ARCHITECTURE-ESSENTIALS.md:167-174`), and the constitution's evidence-over-prose rule (`CLAUDE.md:64-65`). Fix: bind contract, assigned worker, evidence producer, checker principal, execution/revision receipt, and have a trusted collector/checker obtain or authenticate the actual artifacts; add a self-grading RED.

2. [BREAK] **T12 accepts fabricated reminder completion evidence.** `DeliveryEvidence` contains only an occurrence string and timestamp; `AckEvidence` is the same, and `gradeOne` merely finds matching strings (`internal/kernel/checker/checker.go:75-83,171-189`). Empty occurrence IDs and zero timestamps are not rejected. Two locally constructed structs therefore satisfy “durable delivery receipt + user ack” with no durable receipt, provider/message identity, journal reference, or user-authenticated acknowledgement. That is weaker than HARDQ B5 (`docs/HARDQ-CONSOLIDATED.md:90-96`) and T12. Fix: grade durable journal/receipt references from trusted owners, validate non-zero identity/time and acknowledgement provenance, and RED forged/zero/non-durable evidence.

3. [BREAK] **T12's first-match policy lets contradictory evidence be hidden by ordering.** Exit and file-hash criteria return on the first matching-kind/path record (`internal/kernel/checker/checker.go:150-169`). For an expected exit 0, bundle `[exit 0, exit 1]` passes while the reversed bundle fails; likewise, a matching hash before a conflicting hash passes. An evidence producer can prepend a favorable duplicate. Fix: either reject duplicate evidence for each unique contract key or require every applicable record to agree; add permutation and contradictory-duplicate REDs.

4. [RED] **The coding checker REDs validate implementation equality, not real evidence.** `TestCodingStyleContract` uses the non-SHA-256 literal `"abc123"` as both expected and observed hash (`internal/kernel/checker/checker_test.go:34-59`), so it cannot detect that no file is read, no digest shape is validated, and no command produced the exit. This acceptance test cannot prove E13's “real exit code” or artifact claim. Add trusted-collector integration REDs with a fresh file and real process, plus an ablation where the worker supplies an equal fabricated string.

5. [BREAK] **A rejected second journal opener may mutate the database before the live-writer lease is checked.** T07 added `SyncProjection.Init(*sql.DB)` calls at `internal/kernel/journal/journal.go:211-219`, but the B7 writer lease is not inspected/acquired until lines 231–279 and chain verification is later still. A second live handle (or an opener of a tampered DB) can run arbitrary projection SQL—including DDL/DML—then be rejected for the live lease. This retroactively breaks T06's single-writer boundary and HARDQ B7 (`docs/HARDQ-CONSOLIDATED.md:105-116`). Fix: acquire ownership and verify the journal before any projection callback receives a DB handle; RED a second opener whose `Init` attempts a canary write and prove zero mutation.

6. [BREAK] **The “cannot bypass journal” RED demonstrates that bypass succeeds.** `TestProjectionCannotBypassJournal` directly inserts a forged projection row, then implements an ad-hoc test-only orphan scan and calls success when it finds the orphan (`internal/kernel/journal/projection_test.go:104-143`). Production has no such reconciliation gate. Worse, both sync and async projection APIs receive unrestricted `*sql.Tx` (`internal/kernel/journal/projection.go:24-28,77-106`), which can insert into the canonical `events` table. This does not implement Annex P0.3's required rejection with `NON_CANONICAL_WRITE`, canary containment, and no attacker event (`docs/HARNESS-SPEC.md:1394-1402`). Fix: expose a restricted projection transaction/owned repository API rather than raw SQL authority, or enforce DB-level ownership; reproduce the literal canary bypass and require rejection.

7. [OK] **The positive T07 atomicity mechanics are sound within one trusted projection.** `appendOne` constructs the complete canonical event before invoking projections and applies every sync projection before the same transaction commits (`internal/kernel/journal/journal.go:389-439`). Async work and its offset advance share a transaction, and the expected-offset predicate fences two runners (`internal/kernel/journal/projection.go:74-106`). Existing failure/replay tests exercise rollback and monotone offset behavior. This does not cure findings 5–6.

8. [BREAK] **T08 invents cancellation edges outside Annex P0.1's locked tables.** Annex specifies run `CREATED→ADMITTED→RUNNING→{...CANCELLED...}`, turn `CREATED→RUNNING→{...CANCELLED}`, and attempt `PLANNED→AUTHORIZED→RUNNING→{...CANCELLED}` (`docs/HARNESS-SPEC.md:1379-1380`). The implementation additionally allows run cancellation from CREATED and ADMITTED, turn cancellation from CREATED, and attempt cancellation from PLANNED and AUTHORIZED (`internal/kernel/machine/machine.go:98-111,130-137,161-173`). Those are plausible product choices but are not authorized by the exact Annex list. Fix: remove the invented edges or amend the owner contract explicitly; add exhaustive edge-set comparison tests, including cancel from every state and UNKNOWN.

9. [BREAK] **T08 does not implement its recorded-run/checkpoint acceptance.** `Fold` consumes bare event-name strings and returns only one final state (`internal/kernel/machine/machine.go:64-76`); it neither consumes ordered journal events, filters one entity, records a journal-offset checkpoint, nor exposes every intermediate state. The test likewise folds an in-memory slice (`internal/kernel/machine/machine_test.go:13-23`). Therefore it cannot prove “fold of a recorded run reproduces every intermediate state” or “checkpoint = offset” from T08 (`docs/tasks-P0.md:109-114`). Fix: fold typed journal events with entity correlation and offsets, return/checkpoint the last applied offset (and transitions or a callback), and compare against an actually recorded run.

10. [QUALITY] **`Step` contradicts its stated unchanged-on-reject contract.** On an unknown/illegal edge it returns the zero state, not `current` (`internal/kernel/machine/machine.go:48-60`). `Fold` happens to preserve its local state because it ignores that result on error, but a direct caller can overwrite valid state with `Invalid`. Fix the return or narrow the API comment and make the rejected-state behavior explicit in a RED.

11. [BREAK] **T09 performs generic JSON coercion, not per-key schema validation.** Every file key accepts any string, bool, or string array before `applyKey` (`internal/foundation/config/config.go:90-113`). Thus `{"provider_model":true}` becomes model `"true"`; `{"egress_allow":true}` becomes host `"true"`; and array/string forms are accepted for boolean keys. `sandbox_disabled` treats every value except exact lowercase `"true"` as false (`internal/foundation/config/config.go:141-165`), so CLI/env `TRUE`, `1`, or garbage silently disables the attempted setting rather than refusing invalid config. This violates T09's schema-before-merge and invalid-config refusal (`docs/tasks-P0.md:116-121`). Fix: decode each layer into a presence-aware typed schema (or perform strict key-specific parsing), rejecting all noncanonical types/values; RED every layer, not only file JSON.

12. [BREAK] **Unknown environment configuration is silently ignored, despite the claimed all-layer fail-closed rule.** `envLayer` probes only names derived from `knownKeys` and cannot enumerate prefixed inputs (`internal/foundation/config/config.go:118-127`). `NEXUS_CFG_TOTALLY_NEW=1` is therefore invisible, while unknown file/CLI keys reject. The implementation and commit claim unknown keys in *any* layer are refused before merge, and E11 requires unknown typed input to fail closed. Fix: pass an enumerable environment snapshot (or explicitly parse all `NEXUS_CFG_` entries) and reject unknown prefixed names; add env and overridden-lower-layer REDs.

13. [QUALITY] **`egress_allow` parsing is lossy and admits malformed entries.** JSON arrays are joined with commas and later split (`internal/foundation/config/config.go:108-111,157-162`), so a single element containing a comma changes cardinality; empty and whitespace-only entries are accepted; no host normalization occurs. Although the later dialer owns network enforcement, T09's typed config must not lie about what the user supplied. Preserve arrays as arrays, define a strict env/CLI encoding, trim and reject empty/malformed host entries, and RED comma/empty/whitespace cases with origin preserved.

14. [SEC] **A valid `ProfileID` is not a safe path component, allowing profile isolation escape.** `ProfileDir` directly joins the ID into a path (`internal/foundation/pathx/pathx.go:29-35`), while the converged generic ID validator allows `/`, `..`, and path separators (`internal/kernel/contracts/ids.go:28-46`). Profile `../system` resolves into the non-profile system subtree; absolute-looking or nested IDs can collide with other layout locations. This is a T10 consumer-triggered reason to reopen the generic-ID assumption and violates HARDQ B3 physical isolation. Fix: pathx must accept only one canonical segment (or use a separate `ProfileSlug` contract), reject dot/separators, and prove containment with `filepath.Rel` plus traversal REDs.

15. [SEC] **`EnsureDir` does not establish the promised private permissions.** `os.MkdirAll(path, 0700)` leaves an already-existing 0777 directory unchanged (`internal/foundation/pathx/pathx.go:49-54`) and follows symlinked path components. Startup can report success while journal/profile directories are group/world accessible or redirected. Fix: open/lstat and verify ownership, type, containment, and `mode&0077==0` after creation (refuse unsafe existing paths); add pre-created-0777 and symlink REDs.

16. [BREAK] **`Terminate` neither uses the start token for authority nor proves termination, and concurrent `Wait` is unsafe.** It signals `-Token.PID` without first matching the stored start time, ignores every TERM/KILL/Wait error, exposes `Cmd` so another goroutine can call `Wait`, and always returns nil (`internal/foundation/procx/procx_linux.go:49-53,75-90`). After an external/concurrent reap, PID/PGID reuse can target an unrelated group; double-Wait can make the grace branch return early; EPERM/other failures are reported as success. Fix: seal lifecycle ownership behind methods, serialize one Wait, validate the leader token immediately before signaling, preserve syscall errors, and return failure unless the owned group is proven gone; add barrier-controlled Wait/Terminate and stale-token negative controls.

17. [BREAK] **T10 proves a process group, not the claimed spawned tree.** A child can call `setsid`/`setpgid` and escape the leader's group; `Terminate` only signals the original PGID and then declares success (`internal/foundation/procx/procx_linux.go:75-90`). The RED fixture intentionally keeps both shell and grandchild in that group and its oracle enumerates only that PGID (`internal/foundation/procx/procx_linux_test.go:18-45,48-69`), so it cannot see an escaped descendant. Either narrow and document this primitive honestly as group-only until the sandbox/PID-namespace or cgroup owner supplies tree containment, or implement that containment; add an escaped-child RED at the eventual real owner.

18. [BREAK] **T11's “sealed startup snapshot from config + live probes” has no config or attestation binding.** `ProbeResult` is only `{Name, Passed, Detail}` and `Snapshot` contains statuses/order (`internal/kernel/closure/closure.go:107-128`); there is no target/version/config hash, probe ID/revision, evidence reference, expiry, or measurement hash required by Annex P0.5 (`docs/HARNESS-SPEC.md:1540-1543`). A stale result from another config/build can turn a capability ON, and config change invalidation cannot be checked. Fix: bind every probe and the snapshot to the same config/revision/hash and expiry, reject mismatch/staleness, and RED replay after config change.

19. [BREAK] **Duplicate probe names are last-write-wins, so input order controls capability state.** `Seal` overwrites `probeOK[p.Name]` without collision rejection (`internal/kernel/closure/closure.go:142-145`). Supplying `{sandbox:false}` followed by `{sandbox:true}` turns exec ON; reversing them turns it OFF. This defeats fail-closed measurement and seal determinism. Fix: reject duplicate names (or require byte-identical duplicate attestations) and add both-order collision REDs.

20. [RED] **Several acceptance REDs are too narrow to protect the advertised contracts.** T08 checks two illegal edges but not the exhaustive Annex edge set (`internal/kernel/machine/machine_test.go:26-41`); T09 exercises bounds only through file JSON and never malformed env/CLI parsing (`internal/foundation/config/config_test.go:80-96`); T11 repeats the same input to claim determinism and does not permute/collide probes (`internal/kernel/closure/closure_test.go:55-71`). These tests remain green under findings 8, 11–12, and 19. Replace spot checks with spec-enumerated legal/illegal matrices and causal ablations at every input layer.
